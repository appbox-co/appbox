# Für Dokumentation

1. Erstellt eine neue `.mdx`-Datei in einem Abschnittsordner unter `apps/content/docs/en`, zum Beispiel `apps/content/docs/en/apps/jellyfin.mdx`.
2. Fügt das unten beschriebene Frontmatter hinzu und schreibt dann die Seite.

Die Seitenleiste und die Such-Befehlspalette werden von `apps/web/src/config/docs.ts` aus den englischen Dateien erzeugt. Jeder Ordner wird zu einem Abschnitt und jede Datei zu einer Seite darin, sodass eine neue Datei ohne jede Änderung an der Konfiguration erscheint. Ein neuer Ordner legt einen neuen Abschnitt an, deshalb besprecht ihn zuerst in einem Issue.

Schreibt neue Seiten nur auf Englisch. Unter [Docs schreiben](/docs/contributing/writing-docs) findet ihr, wohin Seiten gehören, die Vorlage für App-Seiten und den Styleguide.

## MDX-Dokumenteinstellungen

MDX-Dokumente werden im `apps/content/docs/[language]`- und `apps/content/blog/[language]`-Ordner gespeichert. Jedes Dokument ist eine MDX-Datei, die einen Header mit Metadaten wie Titel und Beschreibung enthält. Hier ist ein Beispiel eines Dokument-Headers:

```mdx
---
title: Document Title
description: Document Description.
sort: 1
---
```

Die folgenden Metadatenfelder werden unterstützt:

- `title` (erforderlich): Der Titel des Dokuments.
- `description` (erforderlich): Eine kurze Beschreibung des Dokuments.
- `sort` (optional): Eine Zahl, die die Reihenfolge des Dokuments in seinem Abschnitt bestimmt. Dokumente mit einem `sort`-Wert kommen zuerst, der niedrigste Wert zuerst. Dokumente ohne diesen Wert folgen danach, alphabetisch nach Titel sortiert.
- `links` (optional): Links zu verwandten Dokumenten, API-Referenzen, Quellcode, etc.
- `toc` (optional): Ob das Inhaltsverzeichnis angezeigt werden soll. Standard ist `true`.

Um neue Metadaten zum Dokument hinzuzufügen, könnt ihr neue Schlüssel zum Header hinzufügen. Beispielsweise könnt ihr einen `author`-Schlüssel hinzufügen, um den Dokumentautor anzugeben:

```mdx
---
title: Document Title
description: Document Description.
sort: 2
author: Author Name
---
```

Beim Hinzufügen benutzerdefinierter Metadaten müsst ihr das Feld jedoch auch zum passenden Schema (`docSchema`, `blogSchema` oder `policySchema`) in `apps/web/src/lib/content/index.ts` hinzufügen. Frontmatter-Schlüssel, die nicht im Schema stehen, werden verworfen.
Danach müsst ihr die neuen Informationen im Dokumenttemplate anzeigen. Dazu müsst ihr die Datei `apps/web/src/app/[locale]/(marketing)/docs/[[...slug]]/page.tsx` oder `apps/web/src/app/[locale]/(marketing)/blog/[[...slug]]/page.tsx` oder eine ihrer Kindkomponenten aktualisieren.

## Eure Änderungen prüfen

Die Website liest die MDX-Dateien direkt, daher zeigt `pnpm dev` Änderungen an, sobald ihr die Seite neu ladet. Wenn das Frontmatter einer Datei ungültig ist, lässt `pnpm dev` diese Seite weg und gibt die Datei und das Feld im Terminal aus. `pnpm build` prüft jede Datei in jeder Sprache und schlägt fehl, wenn eine davon ungültig ist.
