# Για τεκμηρίωση

1. Δημιουργήστε ένα νέο αρχείο `.mdx` σε έναν φάκελο ενότητας μέσα στο `apps/content/docs/en`, για παράδειγμα `apps/content/docs/en/apps/jellyfin.mdx`.
2. Προσθέστε το frontmatter που περιγράφεται παρακάτω και έπειτα γράψτε τη σελίδα.

Το `apps/web/src/config/docs.ts` δημιουργεί την πλαϊνή μπάρα και την παλέτα εντολών αναζήτησης από τα αγγλικά αρχεία. Κάθε φάκελος γίνεται ενότητα και κάθε αρχείο γίνεται σελίδα μέσα σε αυτήν, οπότε ένα νέο αρχείο εμφανίζεται χωρίς καμία αλλαγή στις ρυθμίσεις. Ένας νέος φάκελος προσθέτει μια νέα ενότητα, γι' αυτό συζητήστε τον πρώτα σε ένα issue.

Γράψτε τις νέες σελίδες μόνο στα αγγλικά. Στη σελίδα [Συγγραφή docs](/docs/contributing/writing-docs) θα βρείτε πού τοποθετούνται οι σελίδες, το template για σελίδες εφαρμογών και τον οδηγό ύφους.

## Ρυθμίσεις εγγράφων MDX

Τα έγγραφα MDX αποθηκεύονται στους φακέλους `apps/content/docs/[language]` και `apps/content/blog/[language]`. Κάθε έγγραφο είναι ένα αρχείο MDX που περιέχει μια κεφαλίδα με metadata, όπως τίτλο και περιγραφή. Παρακάτω υπάρχει ένα παράδειγμα κεφαλίδας εγγράφου:

```mdx
---
title: Document Title
description: Document Description.
sort: 1
---
```

Υποστηρίζονται τα παρακάτω πεδία metadata:

- `title` (απαιτείται): Ο τίτλος του εγγράφου.
- `description` (απαιτείται): Μια σύντομη περιγραφή του εγγράφου.
- `sort` (προαιρετικό): Ένας αριθμός που καθορίζει τη σειρά του εγγράφου μέσα στην ενότητά του. Τα έγγραφα με τιμή `sort` εμφανίζονται πρώτα, ξεκινώντας από τη χαμηλότερη. Ακολουθούν τα έγγραφα χωρίς τιμή, ταξινομημένα αλφαβητικά με βάση τον τίτλο.
- `links` (προαιρετικό): Σύνδεσμοι προς σχετικά έγγραφα, API references, source code κ.λπ.
- `toc` (προαιρετικό): Αν θα εμφανίζεται ο πίνακας περιεχομένων. Η προεπιλογή είναι `true`.

Για να προσθέσετε νέα metadata στο έγγραφο, μπορείτε να προσθέσετε νέα keys στην κεφαλίδα. Για παράδειγμα, μπορείτε να προσθέσετε ένα key `author` για να δηλώσετε τον συγγραφέα του εγγράφου:

```mdx
---
title: Document Title
description: Document Description.
sort: 2
author: Author Name
---
```

Όμως, όταν προσθέτετε custom metadata, πρέπει επίσης να προσθέσετε το πεδίο στο αντίστοιχο schema (`docSchema`, `blogSchema` ή `policySchema`) στο `apps/web/src/lib/content/index.ts`. Τα keys του frontmatter που δεν υπάρχουν στο schema απορρίπτονται.
Μετά από αυτό, θα χρειαστεί να εμφανίσετε τη νέα πληροφορία στο template του εγγράφου. Για να το κάνετε αυτό, θα χρειαστεί να ενημερώσετε το αρχείο `apps/web/src/app/[locale]/(marketing)/docs/[[...slug]]/page.tsx`, ή το `apps/web/src/app/[locale]/(marketing)/blog/[[...slug]]/page.tsx`, ή ένα από τα child components του.

## Έλεγχος των αλλαγών σας

Το site διαβάζει απευθείας τα αρχεία MDX, οπότε το `pnpm dev` δείχνει τις αλλαγές μόλις ανανεώσετε τη σελίδα. Αν το frontmatter ενός αρχείου δεν είναι έγκυρο, το `pnpm dev` παραλείπει αυτή τη σελίδα και εμφανίζει στο τερματικό το αρχείο και το πεδίο. Το `pnpm build` ελέγχει κάθε αρχείο σε κάθε γλώσσα και αποτυγχάνει αν κάποιο δεν είναι έγκυρο.
