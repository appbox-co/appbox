# Para documentación

1. Crea un nuevo archivo `.mdx` en una carpeta de sección dentro de `apps/content/docs/en`, por ejemplo `apps/content/docs/en/apps/jellyfin.mdx`.
2. Añade el frontmatter que se describe a continuación y después escribe la página.

La barra lateral y la paleta de comandos de búsqueda las genera `apps/web/src/config/docs.ts` a partir de los archivos en inglés. Cada carpeta se convierte en una sección y cada archivo, en una página de esa sección, de modo que un archivo nuevo aparece sin ningún cambio de configuración. Una carpeta nueva añade una sección nueva, así que coméntala primero en un issue.

Escribe las páginas nuevas solo en inglés. En [Escribir documentación](/docs/contributing/writing-docs) encontrarás dónde van las páginas, la plantilla para páginas de apps y la guía de estilo.

## Configuración de documentos MDX

Los documentos MDX se almacenan en las carpetas `apps/content/docs/[language]` y `apps/content/blog/[language]`. Cada documento es un archivo MDX que contiene un encabezado con metadatos, como título y descripción. A continuación tienes un ejemplo de encabezado de documento:

```mdx
---
title: Document Title
description: Document Description.
sort: 1
---
```

Se admiten los siguientes campos de metadatos:

- `title` (obligatorio): el título del documento.
- `description` (obligatorio): una breve descripción del documento.
- `sort` (opcional): un número que determina el orden del documento dentro de su sección. Los documentos con un valor de `sort` van primero, de menor a mayor. Después van los que no lo tienen, ordenados alfabéticamente por título.
- `links` (opcional): enlaces a documentos relacionados, referencias de API, código fuente, etc.
- `toc` (opcional): si se debe mostrar la tabla de contenidos. Por defecto es `true`.

Para añadir nuevos metadatos al documento, puedes agregar nuevas claves al encabezado. Por ejemplo, puedes añadir una clave `author` para indicar el autor del documento:

```mdx
---
title: Document Title
description: Document Description.
sort: 2
author: Author Name
---
```

Pero al añadir metadatos personalizados, también tienes que añadir el campo al esquema correspondiente (`docSchema`, `blogSchema` o `policySchema`) en `apps/web/src/lib/content/index.ts`. Las claves del frontmatter que no están en el esquema se descartan.
Después, tendrás que mostrar la nueva información en la plantilla del documento. Para hacerlo, actualiza el archivo `apps/web/src/app/[locale]/(marketing)/docs/[[...slug]]/page.tsx`, o `apps/web/src/app/[locale]/(marketing)/blog/[[...slug]]/page.tsx`, o alguno de sus componentes hijos.

## Comprobar tus cambios

El sitio lee los archivos MDX directamente, así que `pnpm dev` muestra los cambios cuando recargas la página. Si el frontmatter de un archivo no es válido, `pnpm dev` omite esa página e indica en la terminal el archivo y el campo. `pnpm build` comprueba todos los archivos de todos los idiomas y falla si alguno no es válido.
