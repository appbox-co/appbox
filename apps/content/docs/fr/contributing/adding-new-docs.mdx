# Pour la documentation

1. Créez un nouveau fichier `.mdx` dans un dossier de section sous `apps/content/docs/en`, par exemple `apps/content/docs/en/apps/jellyfin.mdx`.
2. Ajoutez le frontmatter décrit ci-dessous, puis rédigez la page.

La barre latérale et la palette de recherche de commandes sont générées par `apps/web/src/config/docs.ts` à partir des fichiers en anglais. Chaque dossier devient une section et chaque fichier une page de cette section : un nouveau fichier apparaît donc sans aucune modification de configuration. Un nouveau dossier ajoute une nouvelle section ; discutez-en donc d'abord dans une issue.

Rédigez les nouvelles pages uniquement en anglais. Consultez [Rédiger la documentation](/docs/contributing/writing-docs) pour l'emplacement des pages, le modèle de page d'application et le guide de style.

## Paramètres des documents MDX

Les documents MDX sont stockés dans les dossiers `apps/content/docs/[language]` et `apps/content/blog/[language]`. Chaque document est un fichier MDX contenant un en-tête avec des métadonnées, comme le titre et la description. Voici un exemple d'en-tête de document :

```mdx
---
title: Document Title
description: Document Description.
sort: 1
---
```

Les champs de métadonnées suivants sont pris en charge :

- `title` (obligatoire) : le titre du document.
- `description` (obligatoire) : une brève description du document.
- `sort` (facultatif) : un nombre qui détermine l'ordre du document dans sa section. Les documents qui ont une valeur `sort` apparaissent en premier, par ordre croissant. Les documents sans valeur viennent ensuite, triés par ordre alphabétique de titre.
- `links` (facultatif) : liens vers des documents associés, références API, code source, etc.
- `toc` (facultatif) : indique s'il faut afficher la table des matières. La valeur par défaut est `true`.

Pour ajouter de nouvelles métadonnées au document, vous pouvez ajouter de nouvelles clés à l'en-tête. Par exemple, vous pouvez ajouter une clé `author` pour indiquer l'auteur du document :

```mdx
---
title: Document Title
description: Document Description.
sort: 2
author: Author Name
---
```

Toutefois, lorsque vous ajoutez des métadonnées personnalisées, vous devez aussi ajouter le champ au schéma correspondant (`docSchema`, `blogSchema` ou `policySchema`) dans `apps/web/src/lib/content/index.ts`. Les clés de frontmatter absentes du schéma sont ignorées.
Ensuite, vous devrez afficher la nouvelle information dans le modèle du document. Pour cela, mettez à jour le fichier `apps/web/src/app/[locale]/(marketing)/docs/[[...slug]]/page.tsx`, ou `apps/web/src/app/[locale]/(marketing)/blog/[[...slug]]/page.tsx`, ou l'un de ses composants enfants.

## Vérifier vos modifications

Le site lit directement les fichiers MDX : `pnpm dev` affiche donc vos modifications lorsque vous actualisez la page. Si le frontmatter d'un fichier n'est pas valide, `pnpm dev` omet cette page et indique le fichier et le champ concernés dans le terminal. `pnpm build` vérifie chaque fichier dans chaque langue et échoue si l'un d'eux n'est pas valide.
