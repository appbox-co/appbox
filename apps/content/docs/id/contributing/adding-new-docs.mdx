# Untuk dokumentasi

1. Buat file `.mdx` baru di folder bagian di bawah `apps/content/docs/en`, misalnya `apps/content/docs/en/apps/jellyfin.mdx`.
2. Tambahkan frontmatter yang dijelaskan di bawah, lalu tulis halamannya.

Sidebar dan command palette pencarian dibuat oleh `apps/web/src/config/docs.ts` dari file berbahasa Inggris. Setiap folder menjadi sebuah bagian dan setiap file menjadi halaman di dalamnya, sehingga file baru akan muncul tanpa perlu mengubah konfigurasi apa pun. Folder baru akan menambahkan bagian baru, jadi diskusikan terlebih dahulu di sebuah issue.

Tulis halaman baru hanya dalam bahasa Inggris. Lihat [Menulis dokumentasi](/docs/contributing/writing-docs) untuk lokasi halaman, template halaman aplikasi, dan panduan gaya.

## Pengaturan Dokumen MDX

Dokumen MDX disimpan di folder `apps/content/docs/[language]` dan `apps/content/blog/[language]`. Setiap dokumen adalah file MDX yang berisi header dengan metadata, seperti judul dan deskripsi. Berikut contoh header dokumen:

```mdx
---
title: Document Title
description: Document Description.
sort: 1
---
```

Field metadata berikut didukung:

- `title` (wajib): Judul dokumen.
- `description` (wajib): Deskripsi singkat dokumen.
- `sort` (opsional): Angka yang menentukan urutan dokumen di dalam bagiannya. Dokumen yang memiliki nilai `sort` muncul lebih dulu, dimulai dari nilai terendah. Dokumen tanpa nilai tersebut menyusul, diurutkan secara alfabetis berdasarkan judul.
- `links` (opsional): Link ke dokumen terkait, referensi API, source code, dan sebagainya.
- `toc` (opsional): Apakah daftar isi ditampilkan. Default-nya `true`.

Untuk menambahkan metadata baru ke dokumen, Anda dapat menambahkan key baru ke header. Misalnya, Anda dapat menambahkan key `author` untuk menunjukkan penulis dokumen:

```mdx
---
title: Document Title
description: Document Description.
sort: 2
author: Author Name
---
```

Namun saat menambahkan metadata custom, Anda juga perlu menambahkan field tersebut ke schema yang sesuai (`docSchema`, `blogSchema`, atau `policySchema`) di `apps/web/src/lib/content/index.ts`. Key frontmatter yang tidak ada di schema akan dibuang.
Setelah itu, Anda perlu menampilkan informasi baru tersebut di template dokumen. Untuk melakukannya, Anda perlu memperbarui file `apps/web/src/app/[locale]/(marketing)/docs/[[...slug]]/page.tsx`, atau `apps/web/src/app/[locale]/(marketing)/blog/[[...slug]]/page.tsx` atau salah satu child component-nya.

## Memeriksa perubahan Anda

Situs membaca file MDX secara langsung, sehingga `pnpm dev` menampilkan perubahan saat Anda memuat ulang halaman. Jika frontmatter sebuah file tidak valid, `pnpm dev` tidak menyertakan halaman tersebut dan menampilkan nama file serta field-nya di terminal. `pnpm build` memeriksa setiap file dalam setiap bahasa dan gagal jika ada yang tidak valid.
