# Per la documentazione

1. Crea un nuovo file `.mdx` in una cartella di sezione sotto `apps/content/docs/en`, ad esempio `apps/content/docs/en/apps/jellyfin.mdx`.
2. Aggiungi il frontmatter descritto di seguito, poi scrivi la pagina.

La barra laterale e la palette dei comandi di ricerca vengono generate da `apps/web/src/config/docs.ts` a partire dai file in inglese. Ogni cartella diventa una sezione e ogni file una pagina al suo interno, quindi un nuovo file compare senza alcuna modifica alla configurazione. Una nuova cartella aggiunge una nuova sezione, quindi parlane prima in una issue.

Scrivi le nuove pagine solo in inglese. Consulta [Scrivere la documentazione](/docs/contributing/writing-docs) per la posizione delle pagine, il template delle pagine delle app e la guida di stile.

## Impostazioni dei documenti MDX

I documenti MDX sono archiviati nelle cartelle `apps/content/docs/[language]` e `apps/content/blog/[language]`. Ogni documento è un file MDX che contiene un'intestazione con metadati, come titolo e descrizione. Di seguito è riportato un esempio di intestazione di documento:

```mdx
---
title: Document Title
description: Document Description.
sort: 1
---
```

Sono supportati i seguenti campi di metadati:

- `title` (obbligatorio): il titolo del documento.
- `description` (obbligatorio): una breve descrizione del documento.
- `sort` (opzionale): un numero che determina l'ordine del documento all'interno della sua sezione. I documenti con un valore `sort` vengono per primi, in ordine crescente. Quelli senza valore seguono, ordinati alfabeticamente per titolo.
- `links` (opzionale): link a documenti correlati, riferimenti API, codice sorgente, ecc.
- `toc` (opzionale): indica se mostrare l'indice. Il valore predefinito è `true`.

Per aggiungere nuovi metadati al documento, puoi aggiungere nuove chiavi all'intestazione. Ad esempio, puoi aggiungere una chiave `author` per indicare l'autore del documento:

```mdx
---
title: Document Title
description: Document Description.
sort: 2
author: Author Name
---
```

Quando aggiungi metadati personalizzati, però, devi anche aggiungere il campo allo schema corrispondente (`docSchema`, `blogSchema` o `policySchema`) in `apps/web/src/lib/content/index.ts`. Le chiavi del frontmatter non presenti nello schema vengono scartate.
Dopodiché, dovrai mostrare le nuove informazioni nel template del documento. Per farlo, dovrai aggiornare il file `apps/web/src/app/[locale]/(marketing)/docs/[[...slug]]/page.tsx`, oppure `apps/web/src/app/[locale]/(marketing)/blog/[[...slug]]/page.tsx` o uno dei suoi componenti figlio.

## Verificare le modifiche

Il sito legge direttamente i file MDX, quindi `pnpm dev` mostra le modifiche quando ricarichi la pagina. Se il frontmatter di un file non è valido, `pnpm dev` esclude quella pagina e riporta nel terminale il file e il campo. `pnpm build` controlla ogni file in ogni lingua e fallisce se uno qualsiasi non è valido.
