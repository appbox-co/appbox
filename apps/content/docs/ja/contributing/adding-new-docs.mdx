# ドキュメントの場合

1. `apps/content/docs/en` 配下のセクションフォルダーに、新しい `.mdx` ファイルを作成します（例: `apps/content/docs/en/apps/jellyfin.mdx`）。
2. 以下で説明する frontmatter を追加してから、ページを書きます。

サイドバーと検索コマンドパレットは、`apps/web/src/config/docs.ts` が英語のファイルから生成します。各フォルダーがセクションになり、各ファイルがそのセクション内のページになるため、新しいファイルは設定を変更しなくても表示されます。新しいフォルダーを作るとセクションが新しく追加されるため、まず issue で相談してください。

新しいページは英語でのみ作成してください。ページの置き場所、アプリページのテンプレート、スタイルガイドについては、[ドキュメントの書き方](/docs/contributing/writing-docs)を参照してください。

## MDX ドキュメント設定

MDX ドキュメントは `apps/content/docs/[language]` と `apps/content/blog/[language]` フォルダーに保存されます。各ドキュメントは MDX ファイルで、タイトルや説明などのメタデータを含むヘッダーを持ちます。以下はドキュメントヘッダーの例です。

```mdx
---
title: Document Title
description: Document Description.
sort: 1
---
```

次のメタデータフィールドに対応しています。

- `title`（必須）: ドキュメントのタイトル。
- `description`（必須）: ドキュメントの短い説明。
- `sort`（任意）: セクション内でのドキュメントの順序を決める数値。`sort` の値を持つドキュメントが先に、値の小さい順に並びます。値を持たないドキュメントはその後に、タイトルのアルファベット順で並びます。
- `links`（任意）: 関連ドキュメント、API リファレンス、ソースコードなどへのリンク。
- `toc`（任意）: 目次を表示するかどうか。既定値は `true` です。

ドキュメントに新しいメタデータを追加するには、ヘッダーへ新しいキーを追加できます。たとえば、文書の著者を示す `author` キーを追加できます。

```mdx
---
title: Document Title
description: Document Description.
sort: 2
author: Author Name
---
```

ただし、カスタムメタデータを追加する場合は、`apps/web/src/lib/content/index.ts` 内の対応するスキーマ（`docSchema`、`blogSchema`、`policySchema` のいずれか）にもそのフィールドを追加する必要があります。スキーマにない frontmatter のキーは破棄されます。
その後、ドキュメントテンプレートに新しい情報を表示する必要があります。これには `apps/web/src/app/[locale]/(marketing)/docs/[[...slug]]/page.tsx` ファイル、または `apps/web/src/app/[locale]/(marketing)/blog/[[...slug]]/page.tsx` ファイル、もしくはその子コンポーネントのいずれかを更新します。

## 変更の確認

サイトは MDX ファイルを直接読み込むため、`pnpm dev` ではページを再読み込みすると変更が反映されます。ファイルの frontmatter が無効な場合、`pnpm dev` はそのページを除外し、該当するファイルとフィールドをターミナルに出力します。`pnpm build` はすべての言語のすべてのファイルをチェックし、無効なものが 1 つでもあれば失敗します。
