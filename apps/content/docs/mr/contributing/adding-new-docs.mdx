# दस्तऐवजीकरणासाठी

1. `apps/content/docs/en` अंतर्गत एखाद्या विभाग फोल्डरमध्ये नवीन `.mdx` फाइल तयार करा, उदा. `apps/content/docs/en/apps/jellyfin.mdx`.
2. खाली वर्णन केलेला frontmatter जोडा, मग पेज लिहा.

साइडबार आणि शोध कमांड पॅलेट हे `apps/web/src/config/docs.ts` द्वारे इंग्रजी फाइल्सवरून तयार केले जातात. प्रत्येक फोल्डर एक विभाग बनतो आणि प्रत्येक फाइल त्या विभागातील एक पेज बनते, त्यामुळे कोणताही कॉन्फिगरेशन बदल न करता नवीन फाइल दिसू लागते. नवीन फोल्डरमुळे नवीन विभाग जोडला जातो, म्हणून आधी एखाद्या issue मध्ये त्यावर चर्चा करा.

नवीन पेज फक्त इंग्रजीत लिहा. पेज कुठे ठेवायची, अॅप पेज टेम्पलेट आणि स्टाइल गाइड यांसाठी [दस्तऐवज लिहिणे](/docs/contributing/writing-docs) पाहा.

## MDX दस्तऐवज सेटिंग्ज

MDX दस्तऐवज `apps/content/docs/[language]` आणि `apps/content/blog/[language]` फोल्डरमध्ये साठवले जातात. प्रत्येक दस्तऐवज ही एक MDX फाइल असते ज्यात शीर्षक आणि वर्णनासारख्या मेटाडेटासह हेडर असतो. खाली दस्तऐवज हेडरचे उदाहरण आहे:

```mdx
---
title: Document Title
description: Document Description.
sort: 1
---
```

खालील मेटाडेटा फील्ड समर्थित आहेत:

- `title` (आवश्यक): दस्तऐवजाचे शीर्षक.
- `description` (आवश्यक): दस्तऐवजाचे थोडक्यात वर्णन.
- `sort` (पर्यायी): दस्तऐवजाचा त्याच्या विभागातील क्रम ठरवणारी संख्या. ज्या दस्तऐवजांना `sort` मूल्य आहे ते आधी येतात, कमी मूल्य आधी. ज्यांना हे मूल्य नाही ते त्यानंतर येतात आणि शीर्षकानुसार वर्णक्रमाने लावले जातात.
- `links` (पर्यायी): संबंधित दस्तऐवज, API संदर्भ, स्रोत कोड इत्यादींचे दुवे.
- `toc` (पर्यायी): अनुक्रमणिका दाखवायची की नाही. डीफॉल्ट `true`.

दस्तऐवजात नवीन मेटाडेटा जोडण्यासाठी, तुम्ही हेडरमध्ये नवीन की जोडू शकता. उदाहरणार्थ, दस्तऐवज लेखक दाखवण्यासाठी `author` की जोडता येते:

```mdx
---
title: Document Title
description: Document Description.
sort: 2
author: Author Name
---
```

परंतु कस्टम मेटाडेटा जोडताना, `apps/web/src/lib/content/index.ts` मधील संबंधित स्कीमामध्ये (`docSchema`, `blogSchema` किंवा `policySchema`) ते फील्डही जोडावे लागेल. स्कीमामध्ये नसलेल्या frontmatter की वगळल्या जातात.
यानंतर, दस्तऐवज टेम्पलेटमध्ये नवीन माहिती दाखवावी लागेल. त्यासाठी `apps/web/src/app/[locale]/(marketing)/docs/[[...slug]]/page.tsx` फाइल, किंवा `apps/web/src/app/[locale]/(marketing)/blog/[[...slug]]/page.tsx` किंवा त्यातील एखादा child component अपडेट करावा लागेल.

## तुमचे बदल तपासणे

साइट MDX फाइल्स थेट वाचते, त्यामुळे पेज रिफ्रेश केल्यावर `pnpm dev` बदल दाखवतो. एखाद्या फाइलचा frontmatter अवैध असल्यास, `pnpm dev` ते पेज वगळतो आणि टर्मिनलमध्ये फाइल आणि फील्डचे नाव प्रिंट करतो. `pnpm build` प्रत्येक भाषेतील प्रत्येक फाइल तपासतो आणि त्यापैकी कोणतीही अवैध असल्यास अयशस्वी होतो.
