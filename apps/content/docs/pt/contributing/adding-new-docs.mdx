# Para documentação

1. Crie um novo arquivo `.mdx` em uma pasta de seção dentro de `apps/content/docs/en`, como `apps/content/docs/en/apps/jellyfin.mdx`.
2. Adicione o frontmatter descrito abaixo e depois escreva a página.

A barra lateral e a paleta de comandos de busca são geradas por `apps/web/src/config/docs.ts` a partir dos arquivos em inglês. Cada pasta vira uma seção e cada arquivo vira uma página dentro dela, então um novo arquivo aparece sem nenhuma mudança de configuração. Uma nova pasta adiciona uma nova seção, por isso discuta-a primeiro em uma issue.

Escreva novas páginas somente em inglês. Em [Escrevendo documentos](/docs/contributing/writing-docs) você encontra onde colocar as páginas, o template de página de app e o guia de estilo.

## Configurações de documentos MDX

Documentos MDX ficam armazenados nas pastas `apps/content/docs/[language]` e `apps/content/blog/[language]`. Cada documento é um arquivo MDX que contém um cabeçalho com metadados, como título e descrição. Veja abaixo um exemplo de cabeçalho de documento:

```mdx
---
title: Document Title
description: Document Description.
sort: 1
---
```

Os seguintes campos de metadados são compatíveis:

- `title` (obrigatório): O título do documento.
- `description` (obrigatório): Uma breve descrição do documento.
- `sort` (opcional): Um número que determina a ordem do documento na sua seção. Documentos com valor de `sort` aparecem primeiro, do menor para o maior. Os documentos sem esse valor vêm em seguida, ordenados alfabeticamente pelo título.
- `links` (opcional): Links para documentos relacionados, referências de API, código-fonte etc.
- `toc` (opcional): Define se a tabela de conteúdo deve ser exibida. O padrão é `true`.

Para adicionar novos metadados ao documento, você pode incluir novas chaves no cabeçalho. Por exemplo, é possível adicionar uma chave `author` para indicar o autor do documento:

```mdx
---
title: Document Title
description: Document Description.
sort: 2
author: Author Name
---
```

Mas, ao adicionar metadados personalizados, você também precisa adicionar o campo ao esquema correspondente (`docSchema`, `blogSchema` ou `policySchema`) em `apps/web/src/lib/content/index.ts`. Chaves do frontmatter que não estão no esquema são descartadas.
Depois disso, será necessário exibir a nova informação no template do documento. Para isso, atualize o arquivo `apps/web/src/app/[locale]/(marketing)/docs/[[...slug]]/page.tsx`, ou `apps/web/src/app/[locale]/(marketing)/blog/[[...slug]]/page.tsx`, ou um de seus componentes filhos.

## Verificando suas alterações

O site lê os arquivos MDX diretamente, então o `pnpm dev` mostra as alterações quando você atualiza a página. Se o frontmatter de um arquivo for inválido, o `pnpm dev` deixa essa página de fora e mostra o arquivo e o campo no terminal. O `pnpm build` verifica todos os arquivos em todos os idiomas e falha se algum deles for inválido.
