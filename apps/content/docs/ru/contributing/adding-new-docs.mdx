# Для документации

1. Создайте новый файл `.mdx` в папке раздела внутри `apps/content/docs/en`, например `apps/content/docs/en/apps/jellyfin.mdx`.
2. Добавьте frontmatter, описанный ниже, а затем напишите страницу.

Боковая панель и командная палитра поиска формируются в `apps/web/src/config/docs.ts` на основе английских файлов. Каждая папка становится разделом, а каждый файл — страницей в нем, поэтому новый файл появляется без каких-либо изменений в конфигурации. Новая папка добавляет новый раздел, поэтому сначала обсудите это в issue.

Пишите новые страницы только на английском. На странице [Написание документации](/docs/contributing/writing-docs) описано, куда помещать страницы, а также приведены шаблон страницы приложения и руководство по стилю.

## Настройки MDX-документа

MDX-документы хранятся в папках `apps/content/docs/[language]` и `apps/content/blog/[language]`. Каждый документ — это MDX-файл с заголовком метаданных, например title и description. Ниже приведен пример заголовка документа:

```mdx
---
title: Document Title
description: Document Description.
sort: 1
---
```

Поддерживаются следующие поля метаданных:

- `title` (обязательно): заголовок документа.
- `description` (обязательно): краткое описание документа.
- `sort` (необязательно): число, определяющее порядок документа в его разделе. Документы со значением `sort` идут первыми, по возрастанию. За ними следуют документы без этого значения, отсортированные по алфавиту по заголовку.
- `links` (необязательно): ссылки на связанные документы, справочники API, исходный код и т. д.
- `toc` (необязательно): показывать ли оглавление. По умолчанию `true`.

Чтобы добавить в документ новые метаданные, можно добавить новые ключи в заголовок. Например, можно добавить ключ `author`, чтобы указать автора документа:

```mdx
---
title: Document Title
description: Document Description.
sort: 2
author: Author Name
---
```

Но при добавлении пользовательских метаданных также нужно добавить поле в соответствующую схему (`docSchema`, `blogSchema` или `policySchema`) в `apps/web/src/lib/content/index.ts`. Ключи frontmatter, которых нет в схеме, отбрасываются.
После этого новую информацию нужно вывести в шаблоне документа. Для этого обновите файл `apps/web/src/app/[locale]/(marketing)/docs/[[...slug]]/page.tsx`, файл `apps/web/src/app/[locale]/(marketing)/blog/[[...slug]]/page.tsx` или один из их дочерних компонентов.

## Проверка изменений

Сайт читает MDX-файлы напрямую, поэтому `pnpm dev` показывает изменения после обновления страницы. Если frontmatter файла некорректен, `pnpm dev` пропускает эту страницу и выводит в терминал файл и поле. `pnpm build` проверяет все файлы на всех языках и завершается с ошибкой, если какой-либо из них некорректен.
