# డాక్యుమెంటేషన్ కోసం

1. `apps/content/docs/en` కింద ఉన్న ఒక విభాగ ఫోల్డర్‌లో కొత్త `.mdx` ఫైల్‌ను సృష్టించండి, ఉదాహరణకు `apps/content/docs/en/apps/jellyfin.mdx`.
2. క్రింద వివరించిన ఫ్రంట్‌మ్యాటర్‌ను జోడించి, ఆ తర్వాత పేజీని రాయండి.

సైడ్‌బార్, సెర్చ్ కమాండ్ ప్యాలెట్ రెండూ ఇంగ్లీష్ ఫైల్‌ల నుండి `apps/web/src/config/docs.ts` ద్వారా తయారవుతాయి. ప్రతి ఫోల్డర్ ఒక విభాగంగా, అందులోని ప్రతి ఫైల్ ఆ విభాగంలో ఒక పేజీగా మారుతుంది, కాబట్టి కాన్ఫిగరేషన్‌లో ఏ మార్పూ చేయకుండానే కొత్త ఫైల్ కనిపిస్తుంది. కొత్త ఫోల్డర్ కొత్త విభాగాన్ని జోడిస్తుంది, కాబట్టి ముందుగా దాని గురించి ఒక ఇష్యూలో చర్చించండి.

కొత్త పేజీలను ఇంగ్లీష్‌లో మాత్రమే రాయండి. పేజీలు ఎక్కడ ఉంచాలి, యాప్ పేజీ టెంప్లేట్, స్టైల్ గైడ్ గురించి తెలుసుకోవడానికి [డాక్స్ రాయడం](/docs/contributing/writing-docs) చూడండి.

## MDX పత్ర సెట్టింగ్‌లు

MDX పత్రాలు `apps/content/docs/[language]` మరియు `apps/content/blog/[language]` ఫోల్డర్‌లలో నిల్వ చేయబడతాయి. ప్రతి పత్రం ఒక MDX ఫైల్; అందులో శీర్షిక, వివరణ వంటి మెటాడేటాతో కూడిన హెడర్ ఉంటుంది. పత్ర హెడర్‌కు ఉదాహరణ క్రింద ఉంది:

```mdx
---
title: Document Title
description: Document Description.
sort: 1
---
```

క్రింది మెటాడేటా ఫీల్డ్‌లకు మద్దతు ఉంది:

- `title` (అవసరం): పత్రం యొక్క శీర్షిక.
- `description` (అవసరం): పత్రం గురించి సంక్షిప్త వివరణ.
- `sort` (ఐచ్ఛికం): పత్రం దాని విభాగంలో ఏ క్రమంలో ఉండాలో నిర్ణయించే సంఖ్య. `sort` విలువ ఉన్న పత్రాలు ముందుగా వస్తాయి, తక్కువ విలువ ఉన్నది ముందు. విలువ లేని పత్రాలు వాటి తర్వాత, శీర్షిక ఆధారంగా అక్షరక్రమంలో వస్తాయి.
- `links` (ఐచ్ఛికం): సంబంధిత పత్రాలు, API రిఫరెన్స్‌లు, సోర్స్ కోడ్ మొదలైన వాటికి లింకులు.
- `toc` (ఐచ్ఛికం): విషయ సూచికను చూపాలా వద్దా. డిఫాల్ట్‌గా `true`.

పత్రానికి కొత్త మెటాడేటా జోడించాలంటే, హెడర్‌లో కొత్త కీలు జోడించవచ్చు. ఉదాహరణకు, పత్ర రచయితను చూపించడానికి `author` కీని జోడించవచ్చు:

```mdx
---
title: Document Title
description: Document Description.
sort: 2
author: Author Name
---
```

కానీ కస్టమ్ మెటాడేటా జోడించినప్పుడు, ఆ ఫీల్డ్‌ను `apps/web/src/lib/content/index.ts`లోని సంబంధిత స్కీమాలో (`docSchema`, `blogSchema` లేదా `policySchema`) కూడా జోడించాలి. స్కీమాలో లేని ఫ్రంట్‌మ్యాటర్ కీలు వదిలివేయబడతాయి.
ఆ తర్వాత, కొత్త సమాచారాన్ని పత్ర టెంప్లేట్‌లో చూపించాలి. దీని కోసం `apps/web/src/app/[locale]/(marketing)/docs/[[...slug]]/page.tsx` ఫైల్‌ను, లేదా `apps/web/src/app/[locale]/(marketing)/blog/[[...slug]]/page.tsx` ఫైల్‌ను, లేక వాటి చైల్డ్ కంపోనెంట్‌లలో ఏదో ఒకదాన్ని నవీకరించాలి.

## మీ మార్పులను తనిఖీ చేయడం

సైట్ MDX ఫైల్‌లను నేరుగా చదువుతుంది, కాబట్టి పేజీని రిఫ్రెష్ చేసినప్పుడు `pnpm dev` మార్పులను చూపిస్తుంది. ఒక ఫైల్‌లోని ఫ్రంట్‌మ్యాటర్ చెల్లనిదైతే, `pnpm dev` ఆ పేజీని వదిలేసి, ఆ ఫైల్‌ను, ఫీల్డ్‌ను టెర్మినల్‌లో ప్రింట్ చేస్తుంది. `pnpm build` ప్రతి భాషలోని ప్రతి ఫైల్‌ను తనిఖీ చేస్తుంది, వాటిలో ఏదైనా చెల్లనిదైతే విఫలమవుతుంది.
