# สำหรับเอกสาร

1. สร้างไฟล์ `.mdx` ใหม่ในโฟลเดอร์ของหมวดภายใต้ `apps/content/docs/en` เช่น `apps/content/docs/en/apps/jellyfin.mdx`
2. เพิ่ม frontmatter ตามที่อธิบายไว้ด้านล่าง แล้วจึงเขียนหน้าเอกสาร

แถบด้านข้างและ command palette สำหรับการค้นหาสร้างขึ้นจากไฟล์ภาษาอังกฤษโดย `apps/web/src/config/docs.ts` แต่ละโฟลเดอร์จะกลายเป็นหมวด และแต่ละไฟล์จะกลายเป็นหน้าในหมวดนั้น ดังนั้นไฟล์ใหม่จะปรากฏขึ้นโดยไม่ต้องแก้ไขการกำหนดค่าใดๆ โฟลเดอร์ใหม่จะเพิ่มหมวดใหม่ ดังนั้นให้หารือใน issue ก่อน

เขียนหน้าใหม่เป็นภาษาอังกฤษเท่านั้น ดู [การเขียนเอกสาร](/docs/contributing/writing-docs) สำหรับตำแหน่งที่ควรวางหน้า เทมเพลตหน้าแอป และคู่มือสไตล์การเขียน

## การตั้งค่าเอกสาร MDX

เอกสาร MDX ถูกเก็บไว้ในโฟลเดอร์ `apps/content/docs/[language]` และ `apps/content/blog/[language]` เอกสารแต่ละรายการเป็นไฟล์ MDX ที่มีส่วนหัวพร้อมเมตาดาต้า เช่น ชื่อเรื่องและคำอธิบาย ด้านล่างคือตัวอย่างส่วนหัวของเอกสาร:

```mdx
---
title: Document Title
description: Document Description.
sort: 1
---
```

รองรับฟิลด์เมตาดาต้าต่อไปนี้:

- `title` (จำเป็น): ชื่อเรื่องของเอกสาร
- `description` (จำเป็น): คำอธิบายสั้นๆ ของเอกสาร
- `sort` (ไม่บังคับ): ตัวเลขที่กำหนดลำดับของเอกสารภายในหมวดของเอกสารนั้น เอกสารที่มีค่า `sort` จะแสดงก่อน โดยเรียงจากค่าน้อยไปมาก เอกสารที่ไม่มีค่านี้จะแสดงต่อจากนั้น โดยจัดเรียงตามตัวอักษรจากชื่อเรื่อง
- `links` (ไม่บังคับ): ลิงก์ไปยังเอกสารที่เกี่ยวข้อง, API references, ซอร์สโค้ด ฯลฯ
- `toc` (ไม่บังคับ): กำหนดว่าจะแสดงสารบัญหรือไม่ ค่าเริ่มต้นคือ `true`

หากต้องการเพิ่มเมตาดาต้าใหม่ลงในเอกสาร คุณสามารถเพิ่มคีย์ใหม่ในส่วนหัวได้ ตัวอย่างเช่น คุณสามารถเพิ่มคีย์ `author` เพื่อระบุผู้เขียนเอกสาร:

```mdx
---
title: Document Title
description: Document Description.
sort: 2
author: Author Name
---
```

แต่เมื่อเพิ่มเมตาดาต้าแบบกำหนดเอง คุณต้องเพิ่มฟิลด์นั้นลงในสคีมาที่ตรงกัน (`docSchema`, `blogSchema` หรือ `policySchema`) ใน `apps/web/src/lib/content/index.ts` ด้วย คีย์ frontmatter ที่ไม่มีอยู่ในสคีมาจะถูกตัดทิ้ง
หลังจากนั้น คุณจะต้องแสดงข้อมูลใหม่ในเทมเพลตเอกสาร เมื่อต้องการทำสิ่งนี้ คุณจะต้องอัปเดตไฟล์ `apps/web/src/app/[locale]/(marketing)/docs/[[...slug]]/page.tsx` หรือ `apps/web/src/app/[locale]/(marketing)/blog/[[...slug]]/page.tsx` หรือคอมโพเนนต์ลูกตัวใดตัวหนึ่งของไฟล์เหล่านั้น

## การตรวจสอบการเปลี่ยนแปลงของคุณ

เว็บไซต์อ่านไฟล์ MDX โดยตรง ดังนั้น `pnpm dev` จะแสดงการเปลี่ยนแปลงเมื่อคุณรีเฟรชหน้า หาก frontmatter ของไฟล์ใดไม่ถูกต้อง `pnpm dev` จะไม่รวมหน้านั้นไว้ และจะแสดงไฟล์และฟิลด์นั้นในเทอร์มินัล `pnpm build` จะตรวจสอบทุกไฟล์ในทุกภาษา และจะล้มเหลวหากมีไฟล์ใดไม่ถูกต้อง
