# Для документації

1. Створіть новий файл `.mdx` у папці розділу в `apps/content/docs/en`, наприклад `apps/content/docs/en/apps/jellyfin.mdx`.
2. Додайте frontmatter, описаний нижче, а потім напишіть сторінку.

Бічну панель і палітру команд пошуку будує з англійських файлів `apps/web/src/config/docs.ts`. Кожна папка стає розділом, а кожен файл у ній — сторінкою цього розділу, тож новий файл з’являється без жодних змін у конфігурації. Нова папка додає новий розділ, тому спершу обговоріть це в issue.

Пишіть нові сторінки лише англійською. Про те, де розміщувати сторінки, а також про шаблон сторінки застосунку й посібник зі стилю див. [Написання документації](/docs/contributing/writing-docs).

## Налаштування MDX документа

MDX документи зберігаються в папках `apps/content/docs/[language]` і `apps/content/blog/[language]`. Кожен документ є MDX файлом, що містить заголовок із метаданими, такими як назва й опис. Нижче наведено приклад заголовка документа:

```mdx
---
title: Document Title
description: Document Description.
sort: 1
---
```

Підтримуються такі поля метаданих:

- `title` (обов’язково): назва документа.
- `description` (обов’язково): короткий опис документа.
- `sort` (необов’язково): число, яке визначає порядок документа в його розділі. Документи зі значенням `sort` йдуть першими, від найменшого значення. Документи без нього йдуть після них і сортуються за назвою в алфавітному порядку.
- `links` (необов’язково): посилання на пов’язані документи, API довідники, вихідний код тощо.
- `toc` (необов’язково): чи показувати зміст. За замовчуванням `true`.

Щоб додати до документа нові метадані, ви можете додати нові ключі до заголовка. Наприклад, можна додати ключ `author`, щоб указати автора документа:

```mdx
---
title: Document Title
description: Document Description.
sort: 2
author: Author Name
---
```

Але під час додавання власних метаданих також потрібно додати поле до відповідної схеми (`docSchema`, `blogSchema` або `policySchema`) у `apps/web/src/lib/content/index.ts`. Ключі frontmatter, яких немає в схемі, відкидаються.
Після цього потрібно показати нову інформацію в шаблоні документа. Для цього оновіть файл `apps/web/src/app/[locale]/(marketing)/docs/[[...slug]]/page.tsx`, або `apps/web/src/app/[locale]/(marketing)/blog/[[...slug]]/page.tsx`, або один із його дочірніх компонентів.

## Перевірка змін

Сайт читає MDX файли напряму, тому `pnpm dev` показує зміни, коли ви оновлюєте сторінку. Якщо frontmatter файлу недійсний, `pnpm dev` пропускає цю сторінку й виводить у терміналі файл і поле. `pnpm build` перевіряє кожен файл кожною мовою і завершується з помилкою, якщо хоч один із них недійсний.
