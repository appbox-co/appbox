# Documentation کے لیے

1. `apps/content/docs/en` کے تحت کسی section folder میں نئی `.mdx` file بنائیں، جیسے `apps/content/docs/en/apps/jellyfin.mdx`۔
2. نیچے بیان کیا گیا frontmatter شامل کریں، پھر page لکھیں۔

Sidebar اور search command palette انگریزی files سے `apps/web/src/config/docs.ts` کے ذریعے بنتے ہیں۔ ہر folder ایک section بن جاتا ہے اور اس میں موجود ہر file ایک page بن جاتی ہے، اس لیے نئی file کسی configuration change کے بغیر نظر آ جاتی ہے۔ نیا folder ایک نیا section شامل کرتا ہے، اس لیے پہلے کسی issue میں اس پر بات کریں۔

نئے pages صرف انگریزی میں لکھیں۔ Pages کہاں رکھے جائیں، app page template اور style guide کے بارے میں جاننے کے لیے [دستاویزات لکھنا](/docs/contributing/writing-docs) دیکھیں۔

## MDX document settings

MDX documents `apps/content/docs/[language]` اور `apps/content/blog/[language]` folders میں stored ہوتے ہیں۔ ہر document ایک MDX file ہے جس میں metadata والا header ہوتا ہے، جیسے title اور description۔ document header کی مثال نیچے ہے:

```mdx
---
title: Document Title
description: Document Description.
sort: 1
---
```

درج ذیل metadata fields supported ہیں:

- `title` (required): document کا title۔
- `description` (required): document کی مختصر description۔
- `sort` (optional): ایک number جو طے کرتا ہے کہ document اپنے section میں کس ترتیب پر آئے گا۔ جن documents کی `sort` value ہو وہ پہلے آتے ہیں، سب سے کم value سب سے پہلے۔ جن کی value نہ ہو وہ ان کے بعد آتے ہیں اور title کے حساب سے alphabetically sorted ہوتے ہیں۔
- `links` (optional): related documents، API references، source code وغیرہ کے links۔
- `toc` (optional): table of contents دکھانا ہے یا نہیں۔ default value `true` ہے۔

Document میں نیا metadata شامل کرنے کے لیے header میں نئی keys add کی جا سکتی ہیں۔ مثال کے طور پر document author بتانے کے لیے `author` key add کر سکتے ہیں:

```mdx
---
title: Document Title
description: Document Description.
sort: 2
author: Author Name
---
```

لیکن custom metadata add کرتے وقت آپ کو وہ field `apps/web/src/lib/content/index.ts` میں متعلقہ schema (`docSchema`، `blogSchema` یا `policySchema`) میں بھی add کرنی ہوگی۔ جو frontmatter keys schema میں نہیں ہیں وہ نکال دی جاتی ہیں۔
اس کے بعد نئی information کو document template میں display کرنا ہوگا۔ اس کے لیے `apps/web/src/app/[locale]/(marketing)/docs/[[...slug]]/page.tsx` file، یا `apps/web/src/app/[locale]/(marketing)/blog/[[...slug]]/page.tsx`، یا اس کے child components میں سے کسی ایک کو update کرنا ہوگا۔

## اپنی changes check کرنا

Site MDX files کو براہ راست پڑھتی ہے، اس لیے page refresh کرنے پر `pnpm dev` changes دکھا دیتا ہے۔ اگر کسی file کا frontmatter invalid ہو تو `pnpm dev` وہ page چھوڑ دیتا ہے اور terminal میں file اور field print کرتا ہے۔ `pnpm build` ہر زبان کی ہر file check کرتا ہے اور اگر ان میں سے کوئی بھی invalid ہو تو fail ہو جاتا ہے۔
